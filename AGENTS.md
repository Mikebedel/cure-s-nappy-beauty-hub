# Project rules
- Use global font tokens for every text family; keep the supplied brand lettering as an image to preserve its identity.
- Keep a single cart presentation in Panier, rendered as a compact overlay by PublicStore; cart navigation carries the background location and return scroll so closing restores the originating page.
- Keep canonical catalog items unique and use category membership for overlapping themes; this prevents duplicated products with different category names.
- Reuse CollectionSections for ranges, duos and accessories on both store pages; duo prices are the sum of existing product prices, not invented promotional prices. There is no customer-composed duo.
- Section titles go through SectionHeading and inner-page headers through PageHero; the accessory set details stay fully visible, never collapsed.
- Centralize add-to-cart feedback in CartProvider and persist the first-add flag separately from cart contents; removing items must not replay onboarding.
- Use the shared product-grid and ProductCard for catalog layouts; consistent tracks keep small categories compact without stretching items.
- Keep each range expansion in its own card with start-aligned grid tracks; expanding one range must not stretch sibling cards.
- All editable site content lives in src/content (types.ts, defaults.ts) and is read through useContent/useCatalog; never hardcode page text, prices, contact details or images in pages. Add a field to SiteContent + defaults + its dashboard screen (src/pages/admin/site) together.
- Images in content are references: "asset:<file name>" for files in src/assets, or a full URL for uploads; always render them through resolveImage.
- Dashboard saves to the Supabase table site_content (migration 20261111090000); when the database is unreachable on a dev machine, it saves to localStorage as a local preview only.
- Orders are only created by the create-order edge function, which re-prices everything with supabase/functions/_shared/pricing.ts; the browser sends ids and quantities only. An order becomes paid only through confirmPayment in supabase/functions/_shared/jeko.ts (signed Jèko webhook, then status re-read from the Jèko API; reference, currency and amount checked).
- supabase/functions/_shared/default-content.json mirrors catalog and delivery from src/content/defaults.ts; regenerate with UPDATE_SERVER_DEFAULTS=1 npx vitest run after changing them.
- Admin access requires a two-factor (aal2) session: the UI gate is AdminMfa in ProtectedAdmin, and has_role(..., 'admin') returns false in the database without aal2. Never add an admin path that bypasses either.
